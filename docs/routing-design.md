# 通用个人规则：业务分类与出口选择分离

## 三层分别维护

1. **节点层**：机场、自有VPS、节点名称、凭据。只在塔台/客户端保存。
2. **业务层**：金融、Crypto、AI/X、国内外以及个人例外。由本仓库维护。
3. **网络层**：DNS、TUN、路由器接管、UDP、证书。由设备和内核决定，不能用一份域名表代替。

节点品牌和国家不再出现在策略依赖中；没有节点必须叫某个名字的要求，也不要求存在“日本节点”或某家机场。当前用户偏好Crypto走日本，是首次手选出口的偏好，不是域名规则能验证的事实。节点出口检查参考[node-quality.md](node-quality.md)。

## 首次选择与稳定性

海外默认和Crypto初始REJECT，用户必须分别选定节点。金融和AI/X默认跟随海外默认，必要时直接选择自己的固定节点。广告组默认REJECT，可暂时转海外默认排错。

这是有意的初始行为，不是为地区组放一个占位符。当前Tower会先保留显式候选、再追加动态节点；这样即使没有可用节点，组也不会因变空而被生成器回退成DIRECT。新增节点通过 `include-all` 纳入候选，现有选择仍由客户端保存情况决定。[Tower解析器](https://github.com/pengchujin/tower/blob/main/Tower/Services/RuleSchemeParser.swift#L398)

“♻️ 自动选择”是唯一的自动切换组，且只作为“🌍 海外默认”的可选候选存在：用户手选它之后才生效，容忍150ms抖动、未使用时不测速，空节点池时同样回到REJECT。金融、Crypto、AI/X刻意不提供自动选项——账户出口换IP可能触发风控，日常换线需求由海外默认一个开关承担即可。[Tower解析器](https://github.com/pengchujin/tower/blob/main/Tower/Services/RuleSchemeParser.swift)对 `url-test` 组与 `include-all`/`filter` 均有原生映射，Mihomo实测该组合通过配置校验。

没有自动按延迟切换账户出口。删掉原来选中的节点、换机场或重新导出后，应检查实际选中项。节点失效不代表规则失效，域名表也不能保证服务接受某个IP。

## 顺序为什么这样排

| 层级 | 意图 |
|---|---|
| 内网域名/私有IP | 路由器、NAS等保持直连；IP匹配不额外触发解析 |
| 明确直连、HSBC China | 大陆银行/Tello等需求在宽泛企业分类之前得到保护 |
| 明确海外例外 | 防止特定域名被较宽的国内或其他分类覆盖 |
| 个人业务例外、业务上游集合 | 金融、Crypto、AI/X保留独立出口，且优先于通用广告库 |
| 广告处理 | 默认拦截，可临时放行；不是不可关闭的硬编码拒绝 |
| 国内域名/CN IP | 国内直连的基础覆盖 |
| 最终海外默认 | 未匹配流量交给用户选择的总出口 |

不保证任何公共列表“永不误判”。本方案让个人修正位于通用列表之前，并用测试保护已知场景。

广告放在业务分类之后是明确取舍：降低金融/交易/AI功能被通用广告库误伤的概率，也会放行归入这些业务的一些统计或追踪端点。若你以后希望更严格隐私，再通过明确的独立拦截例外处理，不把所有相关CDN一刀切拒绝。

## 从ACL4SSR借鉴什么

[ACL4SSR在线模板](https://github.com/ACL4SSR/ACL4SSR/blob/master/Clash/config/ACL4SSR_Online.ini)采用局域网、纠错/广告、服务分类、国内、最终兜底的分层，并把业务组指向统一选择组，广告也能切换。适合借鉴这些维护方式。

不直接照搬其默认自动测速出口、Microsoft全站直连、所有国家/服务组，也不把其中国域名表再叠加到现有中国域名表上。其 `.ini` 是订阅转换工具的配置示例，并非任意客户端可直接导入的通用文件。

此外“广告误杀放行”不等于“强制直连”。ACL4SSR的UnBan列表是纠错用途，其中的海外服务不应未经判断全部加入我们DIRECT名单。[UnBan实际内容](https://github.com/ACL4SSR/ACL4SSR/blob/master/Clash/UnBan.list)

继续使用MetaCubeX单一上游域名体系，不是认定它永远最优，而是降低多套库重叠、冲突和定位错误的成本。[数据来源](https://github.com/MetaCubeX/meta-rules-dat)

## 这次移除了什么绑定

- 自有VPS专线组、地区节点组、全部节点中转组：业务组直接看到启用节点。
- News专用组及共享iCloud端点的特殊代理规则：用户已放弃这项尝试；历史资源保留但新方案不引用。
- Microsoft整个企业域名直连：国内分类直连，其余走海外默认，AI专用域名仍优先进入AI。
- `t-mobile.com`整站强制直连：收窄为Wi-Fi Calling相关的 `wifi.t-mobile.com` 与指定ePDG域名；Tello网站直连保持原偏好。

新增 `rules/proxy.yaml`，为“这个域名明确应该走代理”提供独立位置。它只绑定海外默认，不绑定具体节点。

## 格式兼容与非目标

通用性指**不依赖节点来源**，不代表各内核功能完全一致。Mihomo的逻辑UDP规则仍独立存放；QX不尝试转换它们。Tower对DNS的可映射字段有限；高级DNS留在内核专用片段。QX远程与本地规则的优先级还需按[qx-remote-rules.md](qx-remote-rules.md)处理。

本次只更新公开规则和说明，不修改你的运行配置、不登录银行或交易账户、不更改服务器，不启用News重写/MITM。
