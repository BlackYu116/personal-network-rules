# OpenClash 规则自动更新：覆写模块

静态快照维护方式不变：节点和结构仍由塔台导出上传。覆写模块只解决一件事——**把塔台展开成静态行的 18 个规则集恢复为远程引用**，让改 `rules/*.yaml` 或上游数据更新后，路由器自己跟上，不必重新导出。

使用 [mihomo/openclash-ruleset-overwrite.ini](../mihomo/openclash-ruleset-overwrite.ini)（由 `scripts/gen_overwrites.py` 从 tower.yaml 生成，验证脚本检查同步）。

## 应用步骤（用户在 OpenClash 中操作）

1. OpenClash「运行状态」页顶部 →「覆写模块」→ 左栏底部「+ 添加新模块」。
2. 粘贴 ini 文件全部内容保存；「匹配配置文件」填 `all`。
3. 打开模块的启用开关，然后重启 OpenClash 插件。仅保存不生效，覆写只在插件启动时解析执行；重启可能短暂断网，选方便的时间做。

重启后在「规则集」页应看到 18 个远程规则集（个人 5 个 + MetaCubeX 上游 13 个）开始下载；全部成功后，「规则」页开头是 18 条 RULE-SET，塔台导出的静态行排在后面（同内容冗余，命中前 18 条即返回，行为一致）。

## 降级与回退（已实测）

- 规则集下载失败时内核照常启动：失败的集合不命中，流量落到后面的静态规则，按间隔自动重试。首次下载成功后本地留有缓存，之后断网重启也用缓存。
- 规则集走 `proxy: 🌍 海外默认` 下载；海外默认未选节点时下载会失败，选中后自动恢复。
- 回退：关闭模块开关并重启插件，即回到纯静态导出，无需改其他设置。

## 与既有维护的边界

- 塔台重导出仍用于：换节点、增减机场、改策略组结构、改基础 DNS、改规则顺序。重导出后覆写模块继续生效，无需重做。
- DNS 覆写（Tello 例外、分域名 DNS）在 `dns/mihomo.yaml` 和 OpenClash DNS 覆写设置里，与本模块互不影响。
- 18 条前置规则把 `cn`、`category-ads-all` 等也远程化；若上游某列表误收录域名，个人例外仍在前置规则更前面，修正方式不变。
- 路由器需要约几十 MB 空间放规则集缓存（cn 列表最大，约 7MB YAML）；规则集匹配用域名前缀树，内存与延迟不劣于十几万条静态行。
