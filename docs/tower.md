# 塔台：一次设置，日常只维护来源与GitHub规则

## 一、节点留在塔台

1. 在「订阅」保留两家机场。后续增减来源也在这里完成。
2. 添加自己的DMIT**纯节点**订阅地址，节点名保留DMIT字样。不要把带全部分流的旧DMIT完整配置当作这套规则来源。
3. 确认三个来源已启用；“导出筛选”里确实勾选DMIT和至少一个日本节点。订阅里有日本节点但未勾选，地区组仍可能为空。
4. 可以开启“节点附加订阅名称”区分重名来源；本模板的DMIT匹配允许显示名前后有来源后缀。
5. 打开“过滤订阅节点信息”，检查没有误删真正节点。

公开GitHub只保存规则。不要上传塔台导出的完整配置、原始订阅URL、节点密码或QX证书。

## 二、导入GitHub方案

1. 「规则 → 导入」填README里的Raw HTTPS地址，命名为“个人精简分流”。
2. 等待引用规则下载完成，选用该方案。
3. 打开DMIT、日本和全部节点组，确认候选符合国家。DMIT组和日本组必须非空；当前Tower可能把空组回退为直连。
4. 金融、AI / X、News和海外默认使用DMIT；Crypto默认日本；Tello规则直接DIRECT，不再单设组。
5. 导出后第一次仍需在客户端检查实际选中项：持久化的旧选择可能优先于文件中的第一项。

## 三、两个更新开关分别设置

在「导出 → 设置」：

- 打开塔台时更新订阅：**关闭**。
- 代理集合：**关闭**，节点继续使用手动更新后的快照。
- 优先使用规则集：**开启**，兼容的公共规则交给客户端更新。

“节点手动、规则自动”不是一个开关。配置输出里有远程 `rule-providers`／原生远程过滤资源，才能在客户端更新；被展开成静态规则的部分，需要在塔台刷新并重新导出。

[官方设置说明](https://tower.shenqi.uk/docs/settings/)

## 四、导出到设备

- Mac的Clash/Mihomo客户端、OpenClash：导出Clash配置，先新增为独立配置测试。
- Quantumult X：导出QX原生完整文件，通过文件分享导入。
- Shadowrocket：导出它自己的格式。

不改变已有TUN、路由器网关、UDP模式来强行套模板。先保留可回滚的旧配置，按设备需要处理网络层。

## 五、以后只记三种动作

| 改什么 | 到哪里改 | 如何生效 |
|---|---|---|
| 机场URL或机场数量 | 塔台订阅 | 手动刷新，重新导出 |
| 临时使用另一条线路 | 目标客户端策略组 | 当场生效，按客户端保存选择 |
| 长期域名规则/默认策略 | GitHub tower.yaml | 等检查通过，重新导入同一Raw URL并导出 |

Tower当前“刷新规则”主要刷新引用的子列表，不等于更新GitHub顶层结构。若你的版本不支持原地址覆盖导入，先备份原方案，再删除旧的导入方案、从同URL重新导入；机场来源不需重建。

不要同时长期修改GitHub和塔台本地规则覆盖。让GitHub作为规则源，能避免“不知道哪份覆盖了哪份”。

## Tello特别检查

Tower当前Clash生成器可能重建Fake-IP过滤列表，不保证保留模板DNS例外。导出后检查或在OpenClash持久添加ePDG例外，见[tello.md](tello.md)。如果选择“DNS保护 → 跟随方案”避免Tower额外启用Fake-IP，仍须确认OpenClash自身没有再次覆盖；它不是自动修复按钮。

## QX的私有本机层

Apple News重写引用与MITM证书属于QX本机层，不由本仓库Clash模板提供。以后重新导入QX完整配置前，先备份并保留自己的 `[mitm]` 证书和重写引用；不要把含P12/口令的配置上传GitHub。Tower规则模板不能替代这部分私有设置。

## DMIT订阅“没有找到可识别的节点”

已修复服务端 `nodes.yaml` 的正文格式，原私有URL不变。此前返回JSON（合法YAML），但Tower只用独立的 `proxies:` 行识别Clash节点，导致零节点。现在返回标准块式YAML，UUID、REALITY参数和端口均保持原值。

在塔台订阅页对DMIT来源手动刷新；若之前添加失败而没有保存来源，重新添加原 `nodes.yaml` URL。这里选择“订阅”，不是“规则”。成功后应看到1个名为DMIT的VLESS节点，TLS/REALITY开启，再勾选导出。不要把公开tower.yaml当作DMIT节点源。

如果仍失败，核对是否误用了旧规则模板地址或把本地文件路径当成订阅链接；先查看来源中的最终URL尾部是否为nodes.yaml。不要将完整私有链接截图公开。节点导入成功与网络连通成功是两个验收步骤。

## 精简版迁移

导入新模板后应有8个组，不再出现每家银行和券商各自的策略组。旧方案不会一定被同URL导入自动覆盖；备份后选择新方案，再导出。无需删除两家机场或更换节点凭据。DNS基础地址的集中维护与高级覆写见[dns.md](dns.md)。

## 不同客户端的更新差异

当前Clash/Mihomo可保留本仓库domain YAML的远程引用，供客户端定期更新。当前Tower的QX导出会把这种YAML规则列表展开成本地规则，因此QX需要在塔台刷新规则后重新导出；不能承诺GitHub改完后QX自动同步。

两条Tello UDP500/4500的AND规则是Mihomo侧的辅助兜底；QX当前转换会跳过并提示。QX继续依靠ePDG域名DIRECT，不能把跳过提示当作这两条IP规则已生效。家庭OpenClash的DNS/UDP问题也不会单靠手机规则修好。

此外Tower可能不保留rule-provider的下载代理字段。导出后检查规则资源下载状态；如果Raw下载失败，先解决客户端对GitHub Raw的可达性，不要把“已成功导入方案”等同于“全部规则集已成功下载”。
