# 塔台：通用规则导入和迁移

## 节点来源

在塔台添加或保留你的机场、自有节点，手动刷新，勾选需要导出的节点。节点无须包含特定品牌或国家字样。打开“过滤订阅节点信息”，检查已去掉流量、到期说明等占位项。

规则仓库不包含节点，也不会在线检测节点真实国家、速度或解锁能力。节点名只能辅助辨认。

## 导入规则与首次选择

1. 备份当前可用方案；在塔台“规则 → 导入”使用README里的 `tower.yaml` Raw地址。
2. 选用新方案，应看到9个组：原有海外默认、金融、Crypto、AI/X、广告过滤，加内地/香港/美国/新加坡银行。
3. 先给海外默认、Crypto、香港银行、美国银行、新加坡银行分别手选固定出口；五组初始均为REJECT。内地银行默认DIRECT；金融与AI/X跟随海外默认，也能独立选节点。地区名字只标识业务，不会自动挑相应国家节点。
4. 分别导出Clash/Mihomo、QX或Shadowrocket原生格式，先作为独立配置导入。
5. 客户端中确认实际选中项，再更新全部远程规则资源。未选出口时，通过海外默认下载的资源也可能失败；选择后重试。

旧的专线组、按节点名字筛选的地区组和News组已移除。新增银行地区组按服务域名分类，仍不绑定节点来源。旧配置不会仅因规则子列表更新就自动变成新结构，需要重新导入模板并导出。客户端已保存的旧选择可能影响结果，不要只看YAML中的首项。

## 更新设置

“打开塔台时更新订阅”关闭，“代理集合”关闭，“优先使用规则集”开启。节点用手动刷新的快照；规则是否能在客户端自动更新，取决于导出是否保留了远程引用。

- 更换订阅、增减机场：塔台中操作，刷新节点并重新导出；业务规则无需改变。
- 换出口：客户端策略组手动改选（这是有意的手动动作，模板不含自动切换组）。
- 增加个人域名：GitHub相应 `rules/*.yaml` 小文件。
- 更改组、顺序、基础DNS：GitHub `tower.yaml`，运行 `python scripts/gen_overwrites.py` 重新生成两个派生文件，在塔台重新导入并导出。

当前Tower“刷新规则”主要取子列表，不等于重取顶层模板；不同版本的同URL覆盖行为可能不同。若需删除旧导入方案，先备份，再导入新方案，机场来源不必删除。

## 客户端边界

- QX导出可能把YAML规则展开成大量本地行，详见[qx-remote-rules.md](qx-remote-rules.md)。文件大小和业务规则是否通用是两件事。
- 高级DNS不是Tower无损透传字段，见[dns.md](dns.md)。Tello家庭Wi-Fi问题仍需实际DNS/UDP检查。
- 两条AND规则仅留在 `mihomo/tello-udp.yaml`，不包含在通用方案中。
- Tower可能不保留rule-provider下载代理字段；检查实际资源下载状态，不把“导入方案成功”当作全部规则下载成功。
- 完整重导QX时，备份并保留自己的解析器地址、手动体检任务等本机层。规则仓库不托管私人证书或完整含凭据配置。

[塔台设置手册](https://tower.shenqi.uk/docs/settings/) · [规则解析器](https://github.com/pengchujin/tower/blob/main/Tower/Services/RuleSchemeParser.swift)

## 历史节点格式问题

先前自有节点源返回JSON形式的YAML，Tower逐行识别没有匹配到独立 `proxies:` 行；已在节点源侧修为块式YAML。这个修复与通用业务规则分开维护，不要求以后继续使用该节点。节点订阅放“订阅来源”，公开tower.yaml放“规则方案”，两者不能互换。

## 2026-10-17 地区银行与Tailscale迁移

这次增加了策略组，不能只点“刷新规则”：重新导入同一tower.yaml URL并选用新方案，确认九组后再导出。旧五组配置无法仅靠更新规则子列表创建新组；若启用旧覆写模块，先停用并由用户重导，避免新规则引用不存在的组。

Tailscale节点和认证继续在塔台私有配置中维护，公开模板不包含它。导出时勾选Tailscale节点，保留专用规则在内网通用规则之前；再把完整导出文件交给助手做离线OpenClash优化和验证。验收细项及100段绕过边界见[tailscale.md](tailscale.md)。
